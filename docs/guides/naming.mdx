title: "Naming"

Every name in a generated SDK is something your users type. graft derives them from your spec and
lets you override any of them — and where it has to guess, it tells you.

## The client class

Defaults to `info.title`, PascalCased, with words that describe the *document* rather than the
product removed:

| `info.title` | Client class |
|---|---|
| `Stripe API` | `Stripe` |
| `Acme Platform` | `AcmePlatform` |
| `OpenAI` | `OpenAI` |
| `IBM Cloud` | `IBMCloud` |

`API`, `REST API`, `OpenAPI`, `Specification`, `Spec`, and `Service` are stripped. `Platform` and
`Cloud` are not, because they are plausibly part of a brand — renaming someone's product is worse
than a slightly long class name.

```yaml
name: Acme
```

Sets the class, and everything derived from it: the options type, the default package name, the
[environment variables](/sdk/authentication#credentials-come-from-the-environment-by-default), the
README, and the examples.

<Note>
  No `Client` suffix, deliberately. Fern defaults to `${Namespace}Client`; the SDKs people actually
  enjoy using do not — `new OpenAI()`, `new Anthropic()`, `new Stripe()`. `new Acme()` already says
  "construct a client".

  The one exception is .NET, where a type cannot share a name with a namespace segment. If your package
  is `Acme.Sdk`, the client becomes `AcmeClient` and generation warns — see
  [the .NET caveat](/targets/dotnet#a-naming-caveat).
</Note>

## Environment variable prefix

Derived from the client name, so `Acme` reads `ACME_TOKEN`. Override it when your organisation's
variables were named before the SDK was:

```yaml
name: Acme
envPrefix: ACME_PLATFORM      # ACME_PLATFORM_TOKEN, ACME_PLATFORM_API_KEY, …
```

Separate from `name` because renaming the class to match the variables is the wrong end of the
problem.

## Resources

A resource is the group an operation belongs to — `client.widgets.list()`. graft takes it from the
first path segment, or from a grouping extension when your spec has one.

```yaml
resources:
  assettypes: assetTypes      # rename a resource group
```

Nested groups come from a dotted extension value:

```yaml
paths:
  /orgs/{id}/invoices:
    get:
      x-graft-group: orgs.invoices     # client.orgs.invoices.list()
```

graft reads `x-fern-sdk-group-name` and `x-speakeasy-group` natively, so a spec already annotated for
another generator groups correctly with no config. See [Extensions](/reference/extensions).

## Methods

From `operationId`, or from the HTTP verb and path when there is none. Override per operation:

```yaml
paths:
  /widgets/{id}/archive:
    post:
      x-graft-method: archive          # client.widgets.archive(id)
```

`x-fern-sdk-method-name` and `x-speakeasy-name-override` are read too.

<Warning>
  **graft does not sanitize names it does not understand.** A path `/translations/ass` yields a method
  `ass` — that is the ASS subtitle format, and renaming it would be wrong. If a name reads badly in your
  domain, rename it explicitly; the generator will not second-guess your vocabulary.
</Warning>

## Types

```yaml
models:
  WidgetsResponse:
    rename: Widget
```

Schema keys are frequently written for the document rather than for a consumer — `WidgetsResponse` is
a fine key and a poor type name. Renaming is a one-line edit and it propagates everywhere the type is
mentioned.

Or annotate the schema itself:

```yaml
components:
  schemas:
    WidgetsResponse:
      x-graft-name: Widget
```

Where one schema serves as both a request and a response, `rename` is usually not enough — see
[Read and write models](/guides/read-write-models).

## Splitting lowercase compounds

`assettypes` should be `AssetTypes`, and getting there needs a word list. graft ships one; add your
domain's vocabulary rather than patching the generator:

```yaml
naming:
  words: [clerk, widget, sprocket]
```

The splitter is deliberately conservative, because a wrong split is worse than none: it never splits
a token that is itself a known word, and **every** segment of a proposed split must be recognised.
`assettypes` splits because `asset` and `types` are both known; `fooblarg` stays `Fooblarg`.

## Casing is never yours to choose

You name things in lowercase tokens; each language cases them its own way. One field, six renderings:

| Language | Field |
|---|---|
| TypeScript, Java | `userId` |
| Python | `user_id` |
| Go | `UserID` |
| C# | `UserId` |
| PHP | `$userId` |

This is not configurable, and that is the point. A Go field named `userId` or a Python field named
`userID` is the tell-tale mark of a generated SDK, and no configuration flag should be able to
produce one.

Initialisms come from each language's own convention — Go's `ID`, `URL`, `HTTP` versus C#'s `Id`,
`Url` — which is why the same token sequence has to be re-cased per target rather than cased once in
the IR.
