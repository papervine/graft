---
title: "Custom code"
description: "Add your own methods and files to a generated SDK without losing them on the next generate."
---

Every real SDK grows sugar the spec cannot describe — a convenience method, a helper, a retry wrapper.
graft gives you two ways to add it, and **never destroys it silently**.

## Methods on the generated class

Write between the markers graft emits. Nothing to enable — region preservation is on by default,
because a generated file that invites you to add a method has already promised to keep it:

```ts src/resources/widgets.ts
export class Widgets {
  // …generated methods

  // #region widgets
  /** Sugar: fetch a widget and its tag count in one call. */
  async getWithTags(id: string): Promise<{ widget: Widget; tagCount: number }> {
    const widget = await this.get(id);
    return { widget, tagCount: widget.tags?.length ?? 0 };
  }
  // #endregion widgets
}
```

```ts
await client.widgets.getWithTags('w_1');
```

The method lands on the **real** class, so no subclass and no wrapper to re-export. Regions are
emitted in three places:

| Region | Where | For |
|---|---|---|
| `#region <resource-id>` | each resource class | custom methods on that resource |
| `#region client` | the root client class | cross-resource helpers |
| `#region exports` | `src/index.ts` | re-exporting your own modules |

To opt out, set `preserve.regions: false`. Markers are still emitted; nothing between them is carried.

<Warning>
  If a region holds code and the regenerated file has no matching marker — you renamed it, or the
  resource left the spec — graft **writes nothing** and exits non-zero rather than dropping the code.
  Fix the marker, move the code into a file under `preserve.files`, or pass `--force-overwrite` to
  discard it deliberately.
</Warning>

## Whole files you own

For anything larger — helpers, a custom resource, your own tests — write a normal file and tell
graft to leave it alone:

```yaml graft.yaml
preserve:
  files:
    - src/custom/**
    - README.md
```

Or drop a `.graftignore` in the output directory, using gitignore syntax:

```
src/custom/**
!src/custom/generated-notes.ts
README.md
```

Both are honoured, including under `--clean`: marking a file means it survives, full stop.

## `package.json`

Dependencies you add by hand are kept automatically — no configuration needed:

```sh
$ graft generate openapi.yaml
Wrote 44 files to sdks/typescript
  kept in package.json: dependencies.date-fns, author
```

graft keeps ownership of the fields it derives from your spec and config — `name`, `version`,
`exports`, `files`, `scripts` — and carries everything else across. Where you and graft both declare
a dependency, **your pin wins**: you chose that version on purpose.

## What happens when preservation cannot succeed

<Warning>
  If a region has code on disk and the regenerated file has no matching marker, graft **refuses to
  write anything** and exits `1`. Your code is left exactly as it was.
</Warning>

```
Refusing to write — hand-written code could be lost.

  src/resources/widgets.ts: region `widgets-old` has code but the regenerated file has no such region

Fix the markers, move the code into a file listed under `preserve.files`, or pass
`--force-overwrite` to discard it.
```

This happens when a marker is renamed by hand, or when a resource leaves your spec and takes its
region with it. Your options:

<Steps>
  <Step title="Move the code somewhere durable">
    Put it in a file under `preserve.files`. Best answer if it is not tied to one resource.
  </Step>
  <Step title="Rename the marker to match">
    Look at what graft now emits and align the region name.
  </Step>
  <Step title="Discard it deliberately">
    `graft generate … --force-overwrite`. Only ever an explicit choice, never a default.
  </Step>
</Steps>

Malformed markers are also refused rather than guessed at — an unclosed region, a stray
`#endregion`, a mismatched name, or a duplicated region name. Each one makes automatic placement
ambiguous, and guessing risks moving code somewhere it does not belong.

## Preserved files can go stale

A file graft never writes also never gets improvements. When holding a file back costs you an
update, graft says so:

```
warn: README.md is preserved, but the generator would have changed it — it may be out of date
```

Worth knowing about: a file-level ignore is a trade, and other generators let this drift silently.

## Which to reach for

<AccordionGroup>
  <Accordion title="A method that belongs on a resource">
    Use a **region**. `client.widgets.myHelper()` reads exactly like a generated method, because it
    is on the same class.
  </Accordion>
  <Accordion title="Helpers, utilities, or your own types">
    Use **`preserve.files`**. No markers to keep aligned, and the file is wholly yours.
  </Accordion>
  <Accordion title="Something big, or a different shape entirely">
    Use `preserve.files` for a wrapper class that extends the generated client, and add your wrapper
    to `#region exports` in `src/index.ts` so consumers import yours.
  </Accordion>
</AccordionGroup>

<Tip>
  Markers are the plain `#region` / `#endregion` convention your editor already folds — not
  graft-branded. They carry no dependency on this tool's name.
</Tip>
