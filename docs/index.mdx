---
title: "graft"
description: "An open-source OpenAPI to SDK generator whose output reads as hand-written."
---

graft turns an OpenAPI document into client libraries for six languages that look like somebody wrote
them by hand.

```ts
import { Acme } from '@acme/sdk';

const client = new Acme();                    // reads ACME_TOKEN

const widget = await client.widgets.create({ name: 'Sprocket' });

for await (const widget of client.widgets.list({ limit: 50 })) {
  console.log(widget.id);
}
```

No `id` on create, because the server assigns it. `list` is async-iterable, because that is what
TypeScript developers expect. `widgets.get(id)`, not `widgets.get_(id)`.

## Six languages from one document

| | |
|---|---|
| [TypeScript](/targets/typescript) | zero dependencies, `tsc --noEmit` as a gate |
| [Python](/targets/python) | pydantic models, sync and async, `mypy --strict` |
| [Go](/targets/go) | standard library only, `go vet` as a gate |
| [PHP](/targets/php) | PSR-4, PHPStan level 9 |
| [Java](/targets/java) | records and builders, no Jackson, `-Werror` |
| [.NET](/targets/dotnet) | `sealed record`s, nullable references as errors |

Every judgment — the read/write split, the pagination scheme, the error taxonomy, the hoisted headers
— is made once and every target reads the same answer. So a list operation paginates the same way in
all six while each still looks native: `userId` in TypeScript, `user_id` in Python, `UserID` in Go.

A cross-language conformance suite runs all six SDKs against one real HTTP server and asserts both
that each matched the expected wire trace *and* that every language observed the same thing.

## Generated code that has to compile

Generation **fails** if the output does not pass the target language's own formatter and strict
typechecker — `tsc --noEmit`, `mypy --strict`, `go vet`, PHPStan level 9, `javac -Werror`,
`dotnet build -warnaserror`. A generated SDK that does not typecheck is a bug, not a warning.

## Nothing depends on graft

The transport, retries, auth, pagination, and validation internals are hand-written and vendored into
your package as `core/`. Your published SDK has no runtime dependency on this tool, so nothing that
happens to it can reach your users. [Migrating away](/guides/migrating#migrating-away-from-graft)
costs nothing, which is the point rather than a courtesy.

<Note>
  graft is early, and the project name is a working title. Six languages are implemented; support is
  uneven in the places listed under [Language support](/sdk/capabilities), and each gap is a method
  graft declines to generate rather than one that quietly does the wrong thing.
</Note>
